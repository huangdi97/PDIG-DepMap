# 场景指南（SCENARIO_GUIDE）

场景是 PDIG 的核心入口：**在改变一张卡之前，先知道会发生什么**。

## 四个场景

| 场景           | 它回答的问题                             |
| -------------- | ---------------------------------------- |
| 更换银行卡     | 换卡前：哪些支付、订阅和钱包依赖这张卡？ |
| 银行卡即将到期 | 到期前：哪些支付关系会受影响？           |
| 注销银行卡     | 注销前：哪些支付关系需要迁移？           |
| 更换手机号     | 换号前：哪些账户的登录、恢复与通讯依赖这个手机号？ |

进入方式：首页 → 常用场景（Android），或左侧导航 → 场景（Windows）。

## 发起一个场景

1. 选择场景（换卡 / 到期 / 注销）。
2. 选择要分析的**支付工具**（你确认过的那张卡）。
3. 开始分析。

## 结果怎么看

分析结果分四类：

- **必须处理**：只有这一个已确认的支付方式，换卡/停用后可能无法正常扣款。
  每一项都会说明：为什么必须处理、依据是什么、依赖哪个已确认的关系、不处理可能发生什么。
- **可能还有其他可用方式**：存在其他可用的支付来源，但可能降级（例如备用支付渠道）。
- **需要确认**：当前信息还不足以得出高确定性结论。它会告诉你**需要确认什么**。
- **当前未发现影响**：这次分析没有发现依赖这张卡的关系。

> 注意：**本次分析依据**（覆盖了多少确认信息）与**是否可以继续**（Readiness）是两回事。
> 不存在"87% 安全"这样的评分。

## 从结果到计划

- 有**必须处理**项 → 生成**变更计划**，按"了解 → 准备 → 变更 → 验证"推进。
- 有**需要确认**项 → 先去"需要你处理"补确认，再回来分析。

## 计划状态与下一步

| 状态                   | 意思                 | 点击后       |
| ---------------------- | -------------------- | ------------ |
| 需要先处理必须事项     | 还有必须处理项没完成 | 处理必须事项 |
| 需要继续确认           | 有信息需要你确认     | 继续确认     |
| 需要重新检查           | 分析依据的信息已变化 | 重新检查     |
| 基于当前信息，可以继续 | 可以推进             | 继续下一步   |
| 正在验证               | 等待验证             | 查看验证     |
| 已完成                 | 计划执行完           | 查看结果     |
## 完成操作 ≠ 确认结果

计划里的步骤分两种行为：

- **完成操作**（如"标记完成"）：表示你在现实里做完了这一步。
- **确认结果**（如"确认验证"）：表示结果生效已经得到验证。

只点"完成"，不会自动变成"已验证"。

## 更换手机号：顺序闸门（v0.3.0）

更换手机号使用**先建立、后停用**的流程：

1. **检查旧手机号承担的恢复与认证能力**（准备）
2. **添加新手机号并迁移关键账户**（变更）→ 必须先完成第 1 步
3. **验证新手机号恢复路径**（验证）→ 必须先完成第 2 步
4. **停用旧手机号** → 必须先通过第 3 步的验证

动作列表中的提示会明确写出依赖顺序：

- **必须先完成**：这一步依赖的前置动作
- **完成后才能继续**：依赖这一步的后续动作
- **等待验证**：前置验证类动作还没有通过
- **可以并行处理**：没有先后依赖
- **验证后才能移除旧路径**：停用旧路径前必须已验证新路径

> 该顺序是强制的：前置未完成时，后续动作无法标记完成。
