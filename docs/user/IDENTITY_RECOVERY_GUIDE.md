# 身份与恢复指南（IDENTITY_RECOVERY_GUIDE）

PDIG 不只追踪支付依赖——在 v0.3.0 中，它也帮你把**登录、恢复与通讯**依赖理清楚，尤其是换手机号这种动作。

## 能力维度

| 能力       | 含义                                             |
| ---------- | ------------------------------------------------ |
| 支付       | 资金从哪里来（银行卡、钱包）                     |
| 账户访问   | 能否进入某个账户                                 |
| 登录认证   | 用什么方式验证身份（例如手机号验证码）           |
| 恢复       | 忘记密码/丢失设备时，靠什么找回账户              |
| 通讯       | 渠道本身（例如短信验证码发到哪个手机号）         |

## 三种新关系

- **恢复方式**：A 是恢复 B 账号的方式（例如手机会收到重置验证码）。
- **登录认证**：A 用于登录 B（例如手机号验证码登录）。
- **控制权**：A 控制 B（例如有设备权限的账户）。

> 这些与支付一样，**只有你确认过的关系才是现实**。机器只会提出建议。

## 基础设施薄弱点（v0.3.0）

在「基础设施薄弱点」页面，你会看到三类提示（全部只依据已确认的关系）：

- **只有一个来源，没有备用路径**：某个对象的恢复来源只有一条已确认路径。
  未记录不等于不存在——它只会提示"是否真的没有备用还不确定"。
- **这两个路径依赖同一个故障点**：多条恢复方式其实是同一台设备 / 同一个手机号 / 同一家服务商。
- **发现一个恢复循环**：A 的恢复依赖 B，而 B 的恢复又依赖 A——不能把这种循环当成独立备用路径。

## 更换手机号

见《场景指南》的「更换手机号：顺序闸门」一节。核心一句话：

> **先建立并验证新手机号的恢复路径，才能停用旧手机号。**

期间你会看到明确的流程要求：

- 服务商支持某项能力 ≠ 你已配置该项能力；未确认前只会提示，不会自动确认依赖。
- 动作顺序是强制的：必须先完成 → 完成后才能继续 → 等待验证 → 验证后才能移除旧路径。

## 常见疑问

**为什么"记录里没有备用路径"不等于"真的没有备用"？**
因为 PDIG 只记录你确认过的关系。没记录可能是没导入、没确认，而不是现实里不存在。
所以它不会把"没找到备用"说成"必须处理"，只会提示"需要确认"。

**为什么循环不算独立备用？**
如果 A 的恢复要经过 B，B 的恢复又要经过 A，那么它们在同一个故障圈里，
任何一个出问题都会一起出问题。它不能作为另一个独立来源。
